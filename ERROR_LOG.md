# LinkUp — Issues, Errors & Troubleshooting Log

This document records issues and errors encountered during development and testing, explaining what caused them and how they were solved in a concise, practical manner.

---

## 📋 Log Entries

### 1. PowerShell Script Execution Policy Restriction
* **Error**: `npx : File C:\Program Files\nodejs\npx.ps1 cannot be loaded because running scripts is disabled on this system (PSSecurityException)`.
* **Cause**: Windows PowerShell security policy restricts executing unsigned `.ps1` scripts by default.
* **Solution**: Invoked node/npm commands using `cmd.exe /c` (e.g. `cmd.exe /c "npx tsc ..."`), completely bypassing PowerShell execution policy restrictions.

---

### 2. Backend Authentication Middleware Export Name Mismatch
* **Error**: `TS2305: Module '"../middleware/auth.js"' has no exported member 'requireAuth' / 'AuthenticatedRequest'`.
* **Cause**: `graph.routes.ts` attempted to import `requireAuth` and `AuthenticatedRequest`, but `auth.ts` exports `authenticateToken` and `AuthRequest`.
* **Solution**: Updated imports and route middleware in `backend/src/routes/graph.routes.ts` to use `authenticateToken` and `AuthRequest`.

---

### 3. Route Parameter Type Narrowing in Express
* **Error**: `TS2345: Argument of type 'string | string[]' is not assignable to parameter of type 'string'` on `req.params.cardId`.
* **Cause**: Express TypeScript definitions allow route parameter dictionary values to be `string | string[]`.
* **Solution**: Explicitly narrowed `req.params.cardId` using `const cardId = String(req.params.cardId)`.

---

### 4. Unused Variables Triggering Strict TypeScript Failures
* **Error**: `TS6133: 'Globe' is declared but its value is never read`, `'Layers'`, `'stats'`.
* **Cause**: Strict frontend TypeScript settings (`noUnusedLocals: true`) fail the build on any unreferenced imports or parameters.
* **Solution**: Cleaned up unused Lucide icon imports and incorporated `stats.avgSimilarity` into the interactive graph toolbar stats badge.

---

### 5. High-Dimensional Random Vector Orthogonality in ML Test
* **Error**: `AssertionError: Related topics should have high cosine similarity` in `test_phase4.py`.
* **Cause**: In high-dimensional vector spaces ($D = 384$), random vectors are almost always orthogonal ($\text{similarity} \approx 0$).
* **Solution**: Replaced synthetic random vectors with real sentence embeddings generated by `all-MiniLM-L6-v2` via the `/embed` endpoint. Real texts (AI vs DL vs Pizza) confirmed expected semantic discrimination ($0.78$ vs $-0.02$).

---

### 6. Local PostgreSQL Service Offline During Offline Test Runs
* **Error**: `ECONNREFUSED (10061)` when running test suite while local PostgreSQL server was paused.
* **Cause**: Local Postgres service was inactive or cloud Neon DB connection was not active.
* **Solution**: Enhanced `backend/src/cli/test_all_phases.ts` to detect DB connectivity status gracefully, log a clear notice if offline, and execute all independent unit tests (Bcrypt hashing, JWT generation & verification, CSV and JSON data export serialization).

---

### 7. Signup / Login "Internal Server Error Occurred" (ECONNREFUSED)
* **Error**: `POST /api/auth/signup` returns `500 Internal server error occurred` (`AggregateError [ECONNREFUSED]`).
* **Cause**: The backend received the registration request for `kp99@gmail.com` and attempted to save the user to the `users` table, but the PostgreSQL database is not reachable at `localhost:5432`.
* **Solution**: PostgreSQL service must be running locally, or a cloud PostgreSQL connection string (such as Neon or Supabase) must be configured in `backend/.env` under `DATABASE_URL`.
